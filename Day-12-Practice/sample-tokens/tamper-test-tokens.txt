NOTES:
- ORIGINAL is jwt.io's own example token. It uses HS256 (a shared secret) so jwt.io can verify it
  in the browser with no key download.
- Why not tamper valid-token.txt? That token is RS256 with a placeholder signature
  (SAMPLE_SIGNATURE_NOT_VALID_FOR_VERIFICATION) and no published public key. jwt.io cannot verify
  it at all -- it shows "Unable to automatically download public key" -- so there is no
  "verified" state to break.
- jwt.io's decoder does not let you edit the decoded payload. The JWT Encoder tab builds a NEW
  token and signs it again, so it cannot show tampering. Pasting a pre-built tampered token is the
  way to show it.
